# 电脑硬件价格追踪系统 — 后端答辩报告

---

## 一、项目概述

本项目是一个**电脑硬件价格追踪系统**，数据源来自**中关村在线（ZOL）**。系统实现了硬件产品信息的自动爬取、价格追踪、数据可视化分析及 AI 智能问答功能，覆盖 CPU、GPU、内存、主板、SSD 五大品类。

## 二、我的职责 — 后端开发

我负责整个系统的**后端架构设计与实现**，包括：

1. **NestJS 服务端** — RESTful API 设计与开发
2. **Python 爬虫模块** — 数据采集与清洗
3. **MySQL 数据库** — 数据模型设计与持久化
4. **AI 模块** — LLM 多提供商集成

---

## 三、技术栈

| 层级 | 技术选型 | 选型理由 |
|------|----------|----------|
| 运行时 | Node.js + Python | Node.js 适合高并发 I/O 场景作为 API 服务，Python 生态有最成熟的爬虫工具链 |
| 后端框架 | NestJS + TypeScript | 企业级 Node.js 框架，依赖注入 + 模块化架构，适合多人协作 |
| 爬虫框架 | Scrapy + requests + BeautifulSoup | Scrapy 提供 Pipeline 架构用于数据流管理，requests 绕过反爬检测 |
| 数据库 | MySQL + TypeORM | 关系型数据模型清晰，SQL 查询灵活，TypeORM 提供声明式 Entity 管理 |
| AI 集成 | OpenAI / Anthropic API | 双提供商支持，用户可自由切换 |

## 五、核心模块详解

### 5.1 Products 模块 — 产品管理

**文件**: `server/src/products/products.service.ts`

提供 RESTful 产品 API：

- `GET /api/products` — 支持按品类筛选、模糊搜索、多维度排序
- `GET /api/products/:id` — 单个产品详情
- `GET /api/products/:id/price-history?days=90` — 价格历史时序数据

**关键设计决策**：
- 使用 `MAX(id)` 而非 `MAX(recorded_at)` 获取最新价格，避免同一秒多条记录导致重复行
- 价格历史使用 `INNER JOIN` 按天去重，确保时序图表每天只显示一条记录

### 5.2 Crawl 模块 — 爬虫调度

**文件**: `server/src/crawl/crawl.service.ts`

```
Frontend POST /api/crawl  →  NestJS spawn Python crawler  →  ZOL 网站
        │                          │                              │
        ▼                          ▼                              ▼
  返回 taskId  ←──────  异步执行，不阻塞    ←──────  requests 爬取 + 解析
        │
        ▼
  Frontend 轮询 GET /api/crawl/status/:taskId
        │
        ▼
  crawler 完成 → 预览面板展示结果 → 用户确认保存 → NestJS 调 save.py 写入 DB
```

**架构亮点**：
- **预览-确认机制**：爬取默认使用 `--preview` 模式，结果先展示给用户，人工确认后再写入数据库
- **轮询任务状态**：通过 taskId 机制追踪异步爬取进度，前端每秒轮询
- **跨语言通信**：NestJS ↔ Python 通过 JSON stdout 通信，解耦清晰

### 5.3 Stats 模块 — 统计分析

**文件**: `server/src/stats/stats.service.ts`

```sql
SELECT category, COUNT(*) as product_count,
  ROUND(AVG(latest.price), 2) as avg_price,
  MIN(latest.price) as min_price,
  MAX(latest.price) as max_price
FROM products p
JOIN (
  SELECT product_id, price
  FROM price_history ph1
  WHERE id = (SELECT MAX(id) FROM price_history ph2 WHERE ph2.product_id = ph1.product_id)
) latest ON p.id = latest.product_id
GROUP BY category
```

核心 SQL 通过子查询取每个产品的最新价格，然后按品类聚合统计，前端据此展示仪表盘四卡片（总数、均价、最低、最高）。

### 5.4 AI 模块 — 智能分析

**文件**: `server/src/ai/ai.service.ts` + `providers/openai.provider.ts` + `providers/anthropic.provider.ts`

**双提供商架构**：

```
┌─────────────────────────────────────────┐
│           LLMProvider (接口)              │
│  + chat(messages) → string              │
│  + chatStream(messages) → AsyncGenerator │
└─────────────────────────────────────────┘
          ▲                    ▲
          │                    │
┌─────────┴──────────┐  ┌─────┴──────────────┐
│  OpenAIProvider     │  │  AnthropicProvider  │
│  /chat/completions  │  │  /v1/messages       │
│  SSE stream         │  │  SSE stream         │
└────────────────────┘  └────────────────────┘
```

**四大分析模式**（预设提示词）：

| 模式 | 功能 | 核心提示词 |
|------|------|-----------|
| query | 查价格 | 根据数据库数据回答硬件价格问题 |
| predict | 预测走势 | 分析波动幅度、历史区间、季节性规律 |
| report | 生成报告 | 结构化市场分析：趋势 + 品类动态 + 购买建议 |
| compare | 产品对比 | 多维度性价比对比 |

AI 模块在对话前会查询数据库获取相关产品数据，作为上下文注入 LLM 提示词，实现基于真实数据的智能问答。

## 六、Python 爬虫设计

### 6.1 爬虫架构

**ZOL Spider** (`crawler/zol_scraper/spiders/zol.py`)：

由于 ZOL 对 Scrapy 默认的 Twisted TLS 有反爬检测（返回空 body），Spider **内部使用 `requests` 库**进行 HTTP 请求，Scrapy 框架负责数据流管理和 Pipeline 调度。

**搜索流程**：
1. 构造 URL：`https://detail.zol.com.cn/index.php?c=SearchList&subcateId={id}&keyword={kw}&page={n}`
2. requests.get + BeautifulSoup 解析 HTML
3. 正则匹配 `¥` 符号提取价格（含 `万` 单位转换）
4. 翻页直到数量达标或无结果

**品类 → subcateId 映射**：

| 品类 | subcateId |
|------|-----------|
| CPU | 28 |
| GPU | 6 |
| RAM | 3 |
| MB | 5 |
| SSD | 626 |

### 6.2 数据写入 Pipeline

`crawler/zol_scraper/pipelines.py` — 复用 `db.py` 的 `upsert_product` + `insert_price`：

- **upsert_product**：`ON DUPLICATE KEY UPDATE` 确保同一产品不重复插入
- **insert_price**：每天只记录一条价格（`DATE(recorded_at) = CURDATE()` 去重）

### 6.3 CLI 入口

`crawler/main.py` — 被 NestJS spawn 调用的入口：

```
python main.py <keyword> <category> [count] [--preview]
```

- 参数解析 → category 映射 → 调用 Spider → Pipeline 处理 → JSON stdout 输出
- `--preview` 模式下使用 `PreviewPipeline` 只收集不写入

### 6.4 旧版兼容

`crawler/zol.py` 保留独立版本的 ZOL 搜索解析函数，供旧流程使用，通过 `_request_with_retry` 实现 2 次重试。

## 七、数据库设计

**文件**: `database/schema.sql`

```sql
-- 产品表
CREATE TABLE products (
    id INT AUTO_INCREMENT PRIMARY KEY,
    name VARCHAR(200) NOT NULL,
    category ENUM('CPU','GPU','RAM','MB','SSD') NOT NULL,
    spec VARCHAR(500),
    manmanbuy_url VARCHAR(500),
    image_url VARCHAR(500),
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    UNIQUE KEY uk_name_category (name, category)  -- 同品类产品名唯一
);

-- 价格历史表
CREATE TABLE price_history (
    id INT AUTO_INCREMENT PRIMARY KEY,
    product_id INT NOT NULL,
    price DECIMAL(10,2) NOT NULL,
    source VARCHAR(100) DEFAULT 'zol',
    recorded_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    FOREIGN KEY (product_id) REFERENCES products(id) ON DELETE CASCADE,
    INDEX idx_product_time (product_id, recorded_at)
);

-- AI 提示词表
CREATE TABLE ai_prompts (
    id VARCHAR(50) PRIMARY KEY,
    name VARCHAR(100) NOT NULL,
    description VARCHAR(500),
    content TEXT NOT NULL,
    is_preset TINYINT(1) DEFAULT 0,
    sort_order INT DEFAULT 0,
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    updated_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP
);
```

**设计要点**：
- `UNIQUE(name, category)` 防止同品类产品名重复
- `price_history` 按 `(product_id, recorded_at)` 建索引，加速时序查询
- 价格使用 `DECIMAL(10,2)` 保证精度
- `ON DELETE CASCADE` 删除产品时自动清理价格历史
- `ai_prompts` 的 `is_preset` 字段区分预设提示词和用户自定义

## 八、遇到的挑战与解决方案

### 挑战 1：ZOL 反爬检测

**问题**：Scrapy 默认的 Twisted TLS 握手被 ZOL 服务器拒绝，返回空 body。

**解决**：Spider 内部改用 `requests` 库发送 HTTP 请求，模拟浏览器 User-Agent 和 Cookie，BeautifulSoup 解析 HTML。Scrapy 框架仅作为数据流管理层。

### 挑战 2：跨语言进程通信

**问题**：NestJS（TypeScript）需要调用 Python 爬虫并获取结果。

**解决**：使用 `child_process.spawn` 异步启动 Python 进程，通过 stdout JSON 通信，引入 taskId 轮询机制实现异步非阻塞架构。

### 挑战 3：价格单位不一致

**问题**：ZOL 部分高价产品以"万"为单位（如 ¥2.44万），普通产品直接标价。

**解决**：正则 `[¥￥](\d+\.?\d*)\s*(万)?` 匹配后检测单位，若为"万"则乘以 10000。

### 挑战 4：Scrapy 在 Windows 上的 asyncio 兼容性

**问题**：Python 3.14 + Scrapy 2.16 在 Windows 上存在 asyncio reactor 阻塞问题。

**解决**：绕过 `CrawlerProcess`，手动驱动 Spider → Pipeline 数据流，不依赖 Scrapy 的进程管理。

## 十、项目亮点总结

1. **全栈一体化**：NestJS 直接托管前端静态文件，单进程即可运行前后端
2. **预览-确认机制**：爬取结果先预览后入库，用户拥有完全控制权
3. **双提供商 AI**：同时支持 OpenAI 和 Anthropic，用户可自由切换，支持流式输出
4. **异步爬虫调度**：基于 taskId 轮询的非阻塞爬取架构，前端体验流畅
5. **跨语言协作**：TypeScript + Python 各取所长，通过 JSON stdout 松耦合通信
6. **智能数据库上下文**：AI 对话自动注入相关产品数据作为上下文，回答基于真实数据
7. **可配置提示词**：预设 4 种分析模式 + 用户自定义提示词，灵活扩展

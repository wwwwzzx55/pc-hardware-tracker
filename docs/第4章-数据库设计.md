# 第4章 数据库设计与实现

## 4.1 数据库概述

本系统采用 MySQL 关系型数据库管理系统存储数据，数据库名称为 `pc_hardware_tracker`，字符集选用 `utf8mb4`，排序规则为 `utf8mb4_unicode_ci`，支持存储中文字符及 Emoji 等四字节 Unicode 字符。

数据库共包含三张数据表：**products（产品信息表）**、**price_history（价格历史表）** 和 **ai_prompts（AI提示词表）**。三张表之间的关系为：products 与 price_history 通过外键 `product_id` 构成一对多关系（一个产品对应多条历史价格记录），ai_prompts 为独立配置表，不与其他表产生直接关联。

## 4.2 数据库表结构设计

### 4.2.1 products 产品信息表

产品信息表用于存储从中关村在线（ZOL）爬取的硬件产品基础数据，是系统的核心实体表。该表以自增整数 `id` 作为主键，并在 `name` 与 `category` 字段上建立唯一联合索引 `uk_name_category`，防止同一品类下出现同名重复产品。品类字段采用 ENUM 枚举类型，从数据库层面约束取值范围，确保数据一致性。

<p align="center"><b>表4-1 products 产品信息表</b></p>

| 字段名 | 数据类型 | 长度 | 主键 | 说明 |
|--------|----------|------|:----:|------|
| id | INT | 11 | 是 | 产品唯一标识，自增主键 |
| name | VARCHAR | 200 | 否 | 产品名称，如"Intel 酷睿 i5-14600K"，NOT NULL |
| category | ENUM | — | 否 | 产品品类，取值 CPU/GPU/RAM/MB/SSD，NOT NULL |
| spec | VARCHAR | 500 | 否 | 产品规格参数描述，如核心数、频率、容量等，可为空 |
| manmanbuy_url | VARCHAR | 500 | 否 | 中关村在线产品详情页 URL，可为空 |
| image_url | VARCHAR | 500 | 否 | 产品图片链接地址，可为空 |
| created_at | TIMESTAMP | — | 否 | 记录创建时间，默认 CURRENT_TIMESTAMP |

### 4.2.2 price_history 价格历史表

价格历史表记录每次爬取获得的产品价格快照，是支撑价格趋势分析和 ECharts 图表展示的关键数据表。该表通过 `product_id` 外键关联产品表，设置 `ON DELETE CASCADE` 级联删除——当产品被删除时，其关联的所有价格记录同步清除。在 `(product_id, recorded_at)` 上建立联合索引 `idx_product_time`，优化按产品加时间维度的组合查询。Python 端写入时实现每日去重逻辑，同一产品同一天仅保留一条价格记录，避免冗余。

<p align="center"><b>表4-2 price_history 价格历史表</b></p>

| 字段名 | 数据类型 | 长度 | 主键 | 说明 |
|--------|----------|------|:----:|------|
| id | INT | 11 | 是 | 价格记录唯一标识，自增主键 |
| product_id | INT | 11 | 否 | 关联产品ID，外键引用 products(id)，NOT NULL |
| price | DECIMAL | (10,2) | 否 | 产品价格（单位：元），保留两位小数，NOT NULL |
| source | VARCHAR | 100 | 否 | 价格数据来源标识，默认 'zol'（中关村在线） |
| recorded_at | TIMESTAMP | — | 否 | 价格记录时间，默认 CURRENT_TIMESTAMP |

### 4.2.3 ai_prompts AI提示词表

AI 提示词表用于存储大语言模型对话功能所使用的系统提示词（System Prompt）。该表以字符串类型 `id` 作为主键，使用语义化标识符（如 `query`、`predict`、`report`、`compare`），便于代码中直接引用。系统内置四种预设提示词（查价格、预测走势、生成报告、产品对比），通过 `is_preset` 字段区分预设与用户自定义内容。`updated_at` 字段设置 `ON UPDATE CURRENT_TIMESTAMP`，记录修改时自动刷新时间。

| updated_at | TIMESTAMP | — | 否 | 最后更新时间，更新时自动刷新 |

## 4.3 数据库建表 SQL 语句

    sort_order INT DEFAULT 0,

## 4.4 Python 操作数据库脚本

系统爬虫端使用 Python 语言，通过 `mysql-connector-python` 库与 MySQL 数据库交互，核心操作封装在 `crawler/db.py` 模块中。以下逐一介绍各函数的实现与原理。

### 4.4.1 数据库连接配置

数据库连接参数通过环境变量读取，未设置时使用默认值。该方式使得开发环境与生产环境切换无需修改代码。

```python
import os
import mysql.connector

DB_CONFIG = {
    'host':     os.environ.get('DB_HOST', 'localhost'),
    'user':     os.environ.get('DB_USER', 'root'),
    'password': os.environ.get('DB_PASSWORD', '908%Wang'),
    'database': os.environ.get('DB_NAME', 'pc_hardware_tracker'),
    'charset':  'utf8mb4'
}

def get_connection():
    return mysql.connector.connect(**DB_CONFIG)
```

**讲解**：`os.environ.get(key, default)` 从系统环境变量读取配置，若未设置则回退到默认值。`charset: 'utf8mb4'` 确保中文及四字节 Unicode 字符正确存储。`get_connection()` 将字典解包传递给连接函数，每次调用返回新的连接对象。

### 4.4.2 产品信息写入（操作 products 表）

`upsert_product` 函数实现"存在则更新、不存在则插入"的 UPSERT 语义，确保同一品类下同名产品不会重复录入。

```python
def upsert_product(name, category, spec='', url='', image_url=''):
    """插入或更新产品，返回 product_id"""
    conn = get_connection()
    try:
        cursor = conn.cursor()
        cursor.execute('''
            INSERT INTO products (name, category, spec, manmanbuy_url, image_url)
            VALUES (%s, %s, %s, %s, %s)
            ON DUPLICATE KEY UPDATE
                spec=VALUES(spec),
                manmanbuy_url=VALUES(manmanbuy_url),
                image_url=VALUES(image_url)
        ''', (name, category, spec, url, image_url))
        conn.commit()
        cursor.execute(
            'SELECT id FROM products WHERE name=%s AND category=%s',
            (name, category))
        product_id = cursor.fetchone()[0]
        cursor.close()
        return product_id
    finally:
        conn.close()
```

**讲解**：
- **参数化查询**：所有用户数据通过 `%s` 占位符传递，由驱动自动转义，从根本上防止 SQL 注入。
- **UPSERT 机制**：`ON DUPLICATE KEY UPDATE` 是 MySQL 特有语法——当 INSERT 违反 `uk_name_category` 唯一索引时，不报错，转而更新 `spec`、`manmanbuy_url`、`image_url` 字段为本次提交的新值。
- **事务提交**：`conn.commit()` 显式提交事务。MySQL 连接器默认不自动提交，必须手动调用。
- **连接释放**：`try...finally` 确保无论操作成功或异常，连接都被正确关闭，防止连接泄漏。

### 4.4.3 价格记录写入（操作 price_history 表）

`insert_price` 函数将爬取到的价格写入价格历史表，内置每日去重逻辑——同一产品每天仅保留一条记录。

```python
def insert_price(product_id, price, source='zol'):
    """记录一条价格，同一天已有记录则跳过"""
    conn = get_connection()
    try:
        cursor = conn.cursor()
        # 检查今天是否已有记录
        cursor.execute('''
            SELECT id FROM price_history
            WHERE product_id = %s AND DATE(recorded_at) = CURDATE()
            LIMIT 1
        ''', (product_id,))
        if cursor.fetchone():
            cursor.close()
            return  # 今天已有记录，跳过
        cursor.execute('''
            INSERT INTO price_history (product_id, price, source)
            VALUES (%s, %s, %s)
        ''', (product_id, price, source))
        conn.commit()
        cursor.close()
    finally:
        conn.close()
```

**讲解**：
- **每日去重**：先执行 SELECT 查询，用 `DATE(recorded_at) = CURDATE()` 判断当天是否已有该产品的价格记录。`CURDATE()` 返回当前日期，`DATE()` 将时间戳截断为日期。查询到记录则直接 return 跳过插入。
- **先查后写**：本系统爬虫为单线程执行，不存在并发写入的竞态问题，该方案完全满足实际需求。
- **source 预留**：source 参数标记数据来源，当前固定为 `'zol'`，为未来接入多电商平台预留灵活性。

### 4.4.4 最新价格查询（操作 price_history 表）

`get_latest_price` 函数查询指定产品的最新一条价格记录。

```python
def get_latest_price(product_id):
    """获取某产品最新价格"""
    conn = get_connection()
    try:
        cursor = conn.cursor()
        cursor.execute('''
            SELECT price FROM price_history
            WHERE product_id=%s ORDER BY recorded_at DESC LIMIT 1
        ''', (product_id,))
        row = cursor.fetchone()
        cursor.close()
        return row[0] if row else None
    finally:
        conn.close()
```

**讲解**：`ORDER BY recorded_at DESC LIMIT 1` 按时间降序取第一条即最新记录，利用 `idx_product_time` 联合索引快速定位。`row[0] if row else None` 处理无记录情况，返回 `None` 而非抛异常。

### 4.4.5 批量写入脚本 save.py

`save.py` 由 NestJS 后端以子进程方式调用。用户在前端确认预览爬取结果后，后端将产品 JSON 数组通过管道传入 stdin，脚本逐条调用上述函数写入数据库。

```python
import sys, json
from db import upsert_product, insert_price

def main():
    category = sys.argv[1] if len(sys.argv) > 1 else 'CPU'
    raw = sys.stdin.read().strip()
    items = json.loads(raw)

    results = []
    for item in items:
        product_id = upsert_product(
            item['name'], category,
            url=item.get('url', ''),
            image_url=item.get('img_url', ''))
        insert_price(product_id, item['price'])
        results.append({
            'product_id': product_id,
            'name': item['name'],
            'price': item['price'],
        })

    print(json.dumps({
        'success': True, 'count': len(results), 'products': results
    }, ensure_ascii=False))
```

**讲解**：
- **stdin 通信**：`sys.stdin.read()` 读取后端通过管道传入的完整 JSON 数据。相比命令行参数传递，管道方式无长度限制，且 JSON 不会暴露在进程列表中，更为安全。
- **逐条写入**：遍历 JSON 数组，每个产品依次调用 `upsert_product()` 写 products 表和 `insert_price()` 写 price_history 表，完成一条产品的完整入库。
- **JSON 输出**：结果以 JSON 输出到 stdout，`ensure_ascii=False` 确保中文不被转义为 `\uXXXX`，方便日志查看。

### 4.4.6 爬虫入口脚本 main.py

`main.py` 是爬虫的命令行入口，由 NestJS 通过 `child_process.spawn()` 调用，支持预览和正式两种模式。

```python
CATEGORY_MAP = {
    'CPU': 'CPU', 'cpu': 'CPU',
    'GPU': 'GPU', 'gpu': 'GPU', '显卡': 'GPU',
    'RAM': 'RAM', 'ram': 'RAM', '内存': 'RAM',
    'MB':   'MB',   'mb': 'MB',   '主板': 'MB',
    'SSD':  'SSD',  'ssd': 'SSD', '硬盘': 'SSD',
}

def run_spider(keyword, category, max_items, preview=False):
    from zol_scraper.spiders.zol import ZolSpider
    spider = ZolSpider(keyword=keyword, category=category, max_items=max_items)

    if preview:
        pipeline = PreviewPipeline()       # 仅收集数据，不写库
    else:
        from zol_scraper.pipelines import ProductPipeline
        pipeline = ProductPipeline()       # 调用 db.py 写入数据库

    for item in spider.start_requests():
        pipeline.process_item(item, spider)
```

**讲解**：
- **策略模式**：预览模式下使用 `PreviewPipeline`（仅内存收集后输出 JSON），正式模式下使用 `ProductPipeline`（内部调用 `db.py` 函数写入数据库）。两种 Pipeline 接口一致，通过参数切换行为，体现了开闭原则。
- **品类映射**：`CATEGORY_MAP` 将中文输入（如"显卡"、"内存"）统一映射为标准 ENUM 值，提高用户输入容错性。
- **命令行用法**：`python main.py <关键词> <品类> [数量] [--preview]`

### 4.4.7 价格刷新脚本 refresh_prices.py

`refresh_prices.py` 用于批量刷新数据库中所有已有产品的最新价格。

```python
from db import get_connection, insert_price

def main():
    conn = get_connection()
    cursor = conn.cursor()
    cursor.execute('SELECT id, name, category FROM products ORDER BY id')
    products = cursor.fetchall()
    conn.close()

    for prod_id, name, category in products:
        try:
            from zol import search_zol
            items = search_zol(name, category, max_items=3)
            for item_name, price, url, img_url in items:
                if name.strip() in item_name.strip():
                    insert_price(prod_id, price)
                    break
        except Exception:
            pass  # 单个失败不影响整体
```

**讲解**：
- **全量遍历**：SELECT 不加 WHERE 条件，读取全部产品后逐个重新搜索价格。
- **容错设计**：每个产品包裹在 try...except 中，单个产品爬取失败（如网络超时）不中断整体流程。
- **名称匹配**：爬取结果可能名称不完全一致，用子串匹配 `name.strip() in item_name.strip()` 校验，避免将错误产品的价格写入。
- **复用去重**：调用 `insert_price()` 写入，该函数内置每日去重，同一天重复刷新不会产生冗余数据。

### 4.4.8 各脚本调用关系

```
NestJS 后端
    ├── spawn main.py --preview    →  预览爬取（不写库，JSON 返回前端）
    ├── spawn save.py <category>   →  确认后批量写入 products + price_history
    └── spawn refresh_prices.py    →  刷新全部产品最新价格
              │
              └── 均调用 db.py ──── get_connection()
                                  ├── upsert_product()   → products 表
                                  ├── insert_price()     → price_history 表
                                  └── get_latest_price() → price_history 表
```

所有数据库操作最终收敛到 `db.py` 三个核心函数，形成清晰的分层结构：`db.py` 为数据访问层，`save.py`、`main.py`、`refresh_prices.py` 为业务调用层，各层职责明确，便于维护和扩展。

## 4.5 本章小结

本章介绍了 PC 硬件价格追踪系统的数据库设计方案。系统采用 MySQL 数据库，共设计三张核心数据表：products 存储硬件产品基础信息，price_history 记录价格时间序列数据，ai_prompts 管理 AI 对话提示词模板。表结构设计遵循数据库规范化原则，通过主键保证实体完整性，通过唯一索引 `uk_name_category` 防止产品重复，通过外键 `product_id` 加 `ON DELETE CASCADE` 维护 products 与 price_history 之间的参照完整性，通过联合索引 `idx_product_time` 优化价格趋势查询性能。Python 端通过 `mysql-connector-python` 库操作数据库，核心函数封装在 `db.py` 模块中，提供 UPSERT 写入、每日去重价格记录、最新价格查询等基础操作，供爬虫入口 `main.py`、批量写入 `save.py` 和价格刷新 `refresh_prices.py` 三个业务脚本调用。
